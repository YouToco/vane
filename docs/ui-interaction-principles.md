# Vane Web 交互定调（AI 对话 vs 固化组件）

> 长期团队规范，M3–M7 前端开发一律遵循。2026-07-14 定调（Boss 拍板）。
> 与 [vane/docs/git-workflow.md] 同级，是前端功能实现方式的判定基准。

## 一条分界线

**AI 对话是「意图理解」的入口，不是「执行」的通道。**

凡是能被结构化的操作（时间、范围、开关、阈值、增删）——一律用**固化组件**在前端
完成，直接命中确定性 API。AI 只负责把「用户说不清、要靠理解」的东西变清楚，且必须
**收敛回同一批固化 API**，绝不自己拼参数触发副作用。

## 三条准则

1. **能枚举就别对话** — 时间/频率/开关/阈值这类有限取值，用选择器/滑块/开关，
   不让模型生成（省得它偶尔抽风）。
2. **AI 出「预填」，人点「执行」** — AI 的产物是一张**预填好的固化表单**，副作用
   永远由用户点固化按钮触发，不是 AI 直接调 API。
3. **副作用越大越固化** — 删除、发送、改配置越不可逆，越要走按钮 + 二次确认，
   代码里挡死，不信任何自由文本。

## 逐功能划分

### 纯固化组件（前端确定性，无模型参与）
| 功能 | 实现 |
|---|---|
| 定时任务时间 | 时间选择器 + 频率档位 + 时区。**绝不让 AI 生成 cron**，前端把选择编译成 cron 直接调 API |
| 推送开关 / 频率 | 开关 + 下拉档位 |
| 信源管理 | 列表 + 增删/暂停按钮 + 分类 tab + 抓取状态灯 |
| 打分敏感度 / 阈值 | 滑块，实时预览影响条数 |
| 反馈动作 | 卡片按钮（感兴趣/不感兴趣/静音源），离散动作直接写库 |
| 登录 / 账号 / 权限 | 安全红线，永远表单 + 按钮，AI 不碰 |
| 状态 / 成本监控 | 图表看板 |
| 危险操作确认 | 模态框 + 明确按钮，代码里 fail-closed |

### AI 对话（处理说不清 / 需理解，纯只读或开放式）
| 功能 | 说明 |
|---|---|
| 追问推送详情 | 纯问答，只读无副作用，AI 自由发挥安全 |
| Onboarding 画像采集 | 首次对话式收集行业/关注领域，开放式天生适合对话 |

### 混合（AI 预填 → 人在固化组件上确认执行）
| 功能 | 流程 |
|---|---|
| 自然语言加信源 | 「帮我关注 XX 博主」→ AI 识别来源类型 → 预填信源卡片 → 用户核对点「添加」 |
| 会话式定制调度 | 「每天早8点推科技」→ AI 解析 {08:00, 科技} → 回填时间选择器+标签选择器 → 用户确认点「创建」 |
| 模糊偏好调整 | 「这类内容我腻了」→ AI 译成结构化标签变更 → 画像编辑器高亮预览 → 用户确认保存 |

## 混合模式核心红线

```
用户自然语言 → AI 解析意图 → 回填固化组件 → 用户核对/微调 → 点「执行」→ 确定性 API
                （停在这）      （看得见）       （改得动）      （人触发）
```

**AI 永远停在「预填」那一步，副作用由用户点固化按钮触发。** 这一条同时解决三个诉求：

- **↓ 攻击面**：注入最多让 AI 预填错的值，但用户在 UI 上看得见、且必须点确认——
  副作用不会静默发生。真正调 API 的永远是固化前端代码。
- **↓ 模型不确定性**：模型出错 = 预填错一个数，用户一眼看到改掉，不会错误执行。
  cron/阈值这类精确值根本不经模型。
- **= 体验不打折**：用户不用手填复杂参数，AI 帮你填好；也可以完全不用 AI，直接拖
  时间选择器——两条路都顺。

## 工程落点

- **后端**：所有确定性 API（`schedule_push`/`update_subscription`/`mute_source`...）是
  **唯一的执行入口**。固化组件直接调它；M4 的 AI 工具也只是这批 API 的薄封装——
  人和 AI 走同一道门，安全约束只需在 API 层写一次。
- **前端**：固化组件是主体工作量，值得上精致动效（时间选择器、滑块、卡片过渡）。
  AI 对话框是点缀入口，产物是「预填事件」而非「执行请求」。M4 的 agent 在飞书侧先
  跑通，Dashboard 聊天框 M7 复用同一 agent。
