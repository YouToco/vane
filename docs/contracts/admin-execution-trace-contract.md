# 管理后台执行轨迹契约（7.10-B2）

状态：已实现
风险等级：S（跨租户管理面、模型提示词、工具参数与结果）

## 1. 用户价值

平台管理员无需记忆任何内部 ID，即可按“用户 → 任务 → 单次运行”定位一次真实执行，
专业地查看模型调用与工具调用的完整证据链，用于排查漏报、错误理解、工具失败和成本异常。

## 2. 真相来源

- 运行身份只来自 `task_run_snapshots` 的不可变
  `(tenant_id,user_id,task_id,id)` 锚。
- 运行结局只来自 `task_run_outcomes`，不得根据推送结果反推。
- 082 起模型与工具调用都直接写入 `run_snapshot_id`，并以复合外键同时校验
  snapshot/tenant/user。此前模型调用仅在该运行的 `push_batches.run_snapshot_id`
  和 `idempotency_key = llm_calls.trace_id` 能证明时兼容归因。
- 082 前的工具调用只有在同一 tenant/user 下该 `temporal_workflow_id` 唯一对应
  一个运行快照时才兼容展示；复用 workflow ID 的历史记录视为无法唯一归因，
  不按时间窗口猜测。
- 提示词展示 `llm_calls.system_prompt/user_prompt` 中当时实际发送的文本；
  禁止用当前任务手册、当前策略或当前代码重新拼装。
- 工具参数展示 `tool_calls.arguments` 原文。历史结果只展示持久化的
  `result_preview`；若 `result_size` 大于预览字节数，必须明确标记“历史存储已截断”，
  不得宣称结果全文。
- 082 起 compiled Exa/TikHub 取材账本保存实际请求 JSON 与安全净化后的 8KB
  响应预览；密钥只存在 HTTP header，禁止写入参数或预览。

## 3. 权限与隔离

- 所有端点先执行 `requirePlatformOwner`；普通租户统一返回 404。
- 每条 SQL 都必须同时带目标 `tenant_id,user_id,task_id`，运行详情再加
  `run_snapshot_id`；禁止只凭可猜测的任务 ID 或快照 ID 读取。
- 前端路由只向平台 owner 暴露，但前端隐藏不能代替服务端鉴权。
- 全部响应设置 `Cache-Control: no-store`。

## 4. 查阅审计

- 读取一次运行详情必须追加 `admin_trace_access_events`。
- 审计记录包含管理员身份、目标租户/用户/任务、运行快照和数据库时间。
- 目标运行验证、轨迹读取与审计追加在同一事务中完成；审计写入或提交失败时，
  接口失败关闭且不返回敏感内容。
- 审计账本不提供产品 API 修改或删除；仅随目标租户的明确隐私清除流程删除。

## 5. 呈现

- 三栏主从导航：用户、任务、运行；用户无需输入内部 ID。
- 详情按时间合并成模型/工具调用时间线，不直接铺一整页 JSON。
- 模型卡展示阶段、模型、状态、耗时、token、成本，并分区展示系统提示词、
  用户提示词和模型输出。
- 工具卡展示工具名、类型、供应商、状态、耗时、成本、格式化参数、结果预览与错误。
- 空值、未知计价、失败和历史截断都必须显式呈现，禁止用 0 或“完整”掩盖未知。

## 6. 验收闸门

1. 未登录 401、非平台 owner 404、平台 owner 可读。
2. 伪造任一 tenant/user/task/snapshot 组合均不可串读。
3. 页面内容与数据库持久化提示词/参数逐字一致。
4. 每次详情成功响应恰有一条访问审计；审计写失败则无详情响应。
5. 历史截断结果有醒目标识。
6. 后端受影响包测试、全仓竞态测试、真实 PostgreSQL 迁移测试、前端 lint/build/test
   全部通过后方可合并。
