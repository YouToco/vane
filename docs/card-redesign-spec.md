> **设计来源**：2026-07-15 10:26–11:52 在「刘卓琪的飞书 CLI」会话里做的 18 张卡片原型迭代，
> 原始压缩视图已存档于 [design-archive/2026-07-15-card-design-prototypes.txt](design-archive/2026-07-15-card-design-prototypes.txt)。

## 2. 定稿形态（11:52 原型逐字）

首发态：

```
<card title="Agent 的下一个战场，不是模型，是 Runtime" subtitle="🤖 AI Agent 情报 · 53AI · 3 天前">
「⚡ 92」
**模型能力已经够用，卡住 Agent 上线的是运行时**

执行沙箱、状态管理、浏览器自动化、可观测性——每项都有成熟供应商，但拼成一条完整链路的工程量，
远超小团队的承受范围。OpenRouter 验证了路由，E2B 验证了沙箱，**统一入口仍是空白**。
「为什么与你有关」 你正在自建 Vane 的 agent loop + Temporal 编排，这篇把「薄脚手架 + 状态 /
观测 / 恢复」的取舍讲透了。
[阅读原文](https://…) [👍] [👎] [🔍 深挖]
</card>
```

点击 👎 后（同一张卡原地更新，正文原样保留）：

```
…（正文与按钮不变）…
🚫 已记录：不感兴趣
<form>
哪里不对？说一句，下次就准了（可跳过）...
[提交]
</form>
```

> 压缩视图语法对照：`「x」` = text_tag，`[x]` = button，`[x](url)` = 链接，`**x**` = markdown 加粗，
> `<form>` = 表单容器。

## 3. 与现状（M5 契约 §10.2 / feishu/card.go）的差异

| 元素 | 现状（生产） | 定稿设计 |
|------|--------------|----------|
| header title | 常量 `"见微 Vane"` | **内容标题** |
| header subtitle | 无 | `{emoji} {栏目} · {来源} · {相对时间}` |
| 分数 | 不可见 | **「⚡ NN」text_tag** |
| 正文首行 | 加粗**重复内容标题** | **一句话洞察**（提炼观点，非标题复述） |
| 摘要 | `摘要：…`（生硬前缀） | 正文段落，允许内嵌 `**加粗**` 强调 |
| 为什么与你有关 | `为什么与你有关：…` 纯文本 | **「为什么与你有关」text_tag** + 说明 |
| 阅读原文 | markdown 链接行 | **按钮** |
| 反馈按钮 | `感兴趣｜不感兴趣｜误判｜深度解读` 四个文字 | `[👍] [👎] [🔍 深挖]` 三个图标 |
| 误判入口 | 独立按钮 | **折叠进 👎 后的输入框** |
| 状态行措辞 | `✅ 已反馈：感兴趣` | `🚫 已记录：不感兴趣` |
| 原因收集 | 无 | **点击后出现 form**（`可跳过`，500 字上限） |

## 4. 数据映射（关键：哪些字段有、哪些缺）

| 卡片元素 | 数据来源 | 状态 |
|----------|----------|------|
| title | `content_items.title` | ✅ 现有 |
| 栏目 | `sources.title`（如「OpenAI 官方 News」） | ✅ 现有。原型里的「AI Agent 情报」「Go 生态」正是栏目化的信源名 |
| emoji 前缀 | 按 `sources.type` 派生，或存 `sources.config` | ⚠️ 需定：建议按 type 派生（rss/exa/tikhub_xhs），避免新字段 |
| 来源站点 | `content_items.url` 域名 | ✅ 可派生。**Exa/聚合源下与栏目不同**（栏目=「Exa: Anthropic 动态」，站点=各新闻站），这正是两者分开的意义 |
| 相对时间 | `content_items.published_at` | ✅ 现有（需「今天 / N 天前」格式化） |
| ⚡ 分数 | `deliveries.score` | ✅ 现有。注意契约 §17：该分是**个性化相关分**，跨期不可比；落库存原始分、排序用有效分——**展示用原始分** |
| 一句话洞察 | cardgen LLM 生成 | ⚠️ 需改 prompt（当前产出是标题复述） |
| 正文 | cardgen LLM | ✅ 改 prompt 结构 |
| 为什么与你有关 | cardgen LLM | ✅ 现有 |

**结论：无需新增数据概念**——「栏目」用 `sources.title` 即可，不必等信源插件化。

## 5. 实现要点

1. **cardgen prompt 重写**：产出三段——①一句话洞察（**不得复述标题**）②正文段落 ③为什么与你有关。
   保留既有「证据纪律」段（delivery 48 编造事故的修复）与注入防护段，二者是硬约束不得删。
   不再由 cardgen 拼 `[阅读原文]`（改为按钮，由构卡函数确定性生成——"挂链接留给代码"的原则不变）。
2. **`BuildDeliveryCard` 签名扩展**：现为 `(bodyMD, deliveryID, state)`，需要 title/subtitle/score/url。
   注意契约 CRITICAL：**workflow 包不得 import feishu**，构卡经函数注入——扩展签名会改动注入契约，
   需同步更新 workflow 侧的函数类型定义。
3. **误判语义保留**：去掉的只是按钮**入口**，`misjudged` 动作本身保留——
   👎 = `not_interested`，form 提交 = `misjudged` + `detail`（原因文本）。
   这样数据模型语义不变，**Gate ③ 仍可测**（点 👎 → 填原因 → 提交）。
   契约 §0「misjudged 定义：这条不该推给我」与输入框「哪里不对？」语义一致。
4. **form 提交是新回调类型**：现有 `card.action.trigger` 处理 button callback，
   form submit 的 event 结构不同，需在 `onCardAction` 扩展分支。
5. **幂等与最新为准**：沿用 M5 既有语义——态度可改、追加式事件日志、重复点幂等 toast。
6. **状态行措辞**改为「已记录」（对齐设计）。

## 6. 待定/风险

- **form 提交的飞书事件结构未验证**：原型是 lark-cli 发的，其 form 从未接过真实回调。
  实现前需先用 lark-cli 发一张带 form 的卡并真点一次，抓 `card.action.trigger` 的实际 payload。
- **图标可用性**：10:38 的图标探针列了 25 个候选，但压缩视图看不出哪些真渲染成功；
  定稿用的是 emoji（👍/👎/🔍）而非 `*_outlined` 图标名，实现照 emoji 走即可。
- **卡片 2.0 原始 JSON 不可得**：lark-cli 的 `+chat-messages-list` 只返回压缩视图，
  原型的精确 JSON（颜色、布局参数）无法取回，需按本规格重建并对照截图校验渲染。
- **旧卡兼容**：M5 前的卡无按钮、body_md 空；本次改版后旧卡同样不回填（沿用契约 §17 的自然过渡取舍）。
